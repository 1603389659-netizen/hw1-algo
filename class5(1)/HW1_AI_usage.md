## 二、"真分治"验证手段（防 AI 假分治）

AI 可能给出"看起来像分治但本质是循环 / 尾递归伪装 / 偷用库函数"的代码。本次作业对每个算法都做了以下验证：

### 2.1 合并排序 —— 验证清单

| 验证项 | 验证方法 | 结果 |
|---|---|---|
| 递归深度 ≥ log₂n | 跑 n=16 时应该递归 4 层；读代码确认存在 `if len(nums) <= 1: return` 终止条件 | ✅ 有终止条件，递归深度符合预期 |
| 真 · 分解 | 代码中显式 `mid = len(nums)//2`、`nums[:mid]`、`nums[mid:]` 三个动作 | ✅ L16–L20 正是这三步 |
| 真 · 合并 | 存在独立 merge 函数，双指针扫描、结果数组拼接 | ✅ merge() 在 L27–L45，独立辅助函数 |
| 没有偷用 `sorted()` | 全文检索 `sorted` 关键字，确认不在 merge_sort / merge 内部 | ✅ 只有 binary_search 里对构造好的表做 assert 用了 sorted |
| 跑通正确用例 | main 中 assert `merge_sort([8,3,5,1,9,2]) == [1,2,3,5,8,9]` | ✅ 通过 |
| 时间复杂度实测 | 看 benchmark 中翻倍倍率是否 ≈ 2.0 | ✅ 2.10×，符合 O(n log n) |

**特别注意**：AI 曾出现过一个"假合并"的风险——把 `merge_sort` 写成 `return sorted(nums)`。我通过"检索 sorted 关键字 + 观察 benchmark 中合并耗时是否真的比冒泡快 182 倍"两道关卡拦住了这种偷懒。

### 2.2 二分查找 —— 验证清单

| 验证项 | 验证方法 | 结果 |
|---|---|---|
| 真 · 折半 | 代码中必须有 `mid = (low+high)//2` 和 `low=mid+1` / `high=mid-1` | ✅ L17–L21 正是 |

| 故意破坏前提能翻车 | 在未排序数组上跑，期望返回错误或 -1 | ✅ 对目标 0 返回 -1（本来应该在 idx=8） |

## 三、中间过程的小插曲

1. **binary_search.py 里出现 SyntaxError**：最初用了中文引号 `"找不到"`，Python 把字符串截断了。修正为中文引号换成英文引号。**启示：AI 写代码时会混入中文标点，跑之前一定要真的运行一次。**

2. **故意实验"碰巧对了"**：第一次用 `[7,1,9,3,5,8,2,6,4]` 打乱数组做故意实验时，对 5 和 1 都"碰巧"返回了正确下标——因为 mid 刚好就是那两个元素的位置。后来我换了极端坏数组 `[99,7,1,12,3,20,5,8,0]` 才让翻车现象出现。**启示："证明"前提重要性时不能只靠一次运气，要构造极端用例。**

3. **benchmark 里的 Python 版本差异**：第一次跑合并比冒泡快 209 倍，第二次重跑是 182 倍，数值有轻微波动但量级一致。**启示：做性能结论时不要只看一次运行，要看趋势和倍率均值。**

### 5.2 新踩坑记录（老问题重演 + 新问题）

**坑 1：中文引号 SyntaxError——同一个坑踩了两次**

Step 2 已经踩过这个坑（binary_search.py 里写了中文引号 `"找不到"`）。Step 4 这次又在 benchmark_v2.py 和 ex02_recursion_limit.py 里各犯了一次：写了中文 `"最好情况"`、`"分治"` 把 Python 双引号字符串截断。

**教训**：AI 代码最常见的低级错误之一就是把中文标点直接粘进 Python 字符串。凡是输出 `SyntaxError: invalid syntax` 且定位在 `print("...")` 附近的，第一反应就去查有没有混入中文引号/中文冒号/中文逗号。

**坑 2：数学题没想清楚就写代码——50 万贷款覆盖不了 5000 月供**

我一开始写的 ex03 设定：贷款 50 万、30 年、利率 1%~6%，直接跑出来月供范围是 **1608~2981 元**——根本碰不到目标 5000！

这是一个典型的"先写代码后想数据"错误。应该先算一下利率上限（5.95%）下 50 万 30 年的月供到底有多少，再决定参数。修正方案：**把贷款额调到 100 万**，月供范围变成 3216~5963，正好包围 5000。

**教训**：凡是涉及数学/物理公式的代码，先笔算一个边界确认量级正确，再写代码。5 分钟手算省下 10 分钟 debug。

## 六、最终教训（两次 Step 合起来）

1. **中文标点是 AI 代码第一杀手**——凡是 SyntaxError 先查引号是不是中文。
2. **公式类代码先算边界再写**——5 分钟手算 vs 10 分钟 debug。
3. **"真·递归"最好的证据是**：递归深度 vs log₂n 吻合 + 人为降低上限会炸——两个都要跑。
4. **二分查找的前提有两层**：①输入数组有序，②你的目标在数组数值范围内。两层都要 assert。
5. **自造 vs 轮子永远做基准对比**——你猜不到 C 实现能快多少，benchmark 告诉你真相。
6. **数学概念（减治 vs 分治）别硬记**——查 2~3 处来源交叉验证，比只看一本教材靠谱。
